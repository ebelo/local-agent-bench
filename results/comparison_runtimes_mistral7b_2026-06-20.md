## Key Findings

### ✅ openclaw-react — 5/5 (best)
- Only adapter to pass all 5 tasks
- Uses `openclaw infer model run --local --json` to get a single model response
- Correctly parses the ReAct format and returns clean assistant text
- Higher latency (~10s/task) but reliable
- The OpenClaw infer path appears to add prompt structuring that helps the model follow ReAct format

### ✅ pi-react — 4/5 (good)
- Uses `pi --print --no-session --no-tools --no-context-files --no-skills --no-prompt-templates --no-extensions --offline --mode text`
- Passed filesystem and weather tasks but failed `fs_read_fixture` (NO_TOOL_ATTEMPT — model didn't emit a tool call)
- Fast (~3.8s/task avg)
- Pi's `--print` mode produces clean model output without runtime scaffolding

### ⚠️ raw-ollama-react — 2/5 (baseline)
- Direct Ollama API calls with ReAct prompt
- Passed the two simplest filesystem tasks but failed 3 tasks with NO_TOOL_ATTEMPT
- Model returned Final Answer without attempting tool calls on the harder tasks
- This is the "pure model" baseline — no runtime assistance

### ❌ hermes-react — 0/5 (broken adapter)
- Returns `session_id: 20260620_215557_919a61` instead of model responses
- The `hermes chat --query --quiet --ignore-rules` command outputs session metadata to stdout, not the model's reply
- **Root cause:** The adapter captures stdout but Hermes writes the model response to a different stream or in a different format than expected
- **Fix needed:** Inspect actual Hermes CLI output format and update `HermesChatBackend.chat()` to extract the model reply correctly

### ❌ hermes-native — 0/5 (broken adapter)
- Same issue as hermes-react — returns session IDs
- The native adapter doesn't parse Hermes's response format correctly
- **Fix needed:** Same as hermes-react, plus check how native tool-call responses are structured

### ❌ openclaw-native — 0/5 (broken adapter)
- Error: `Model override "ollama/mistral:7b" is not allowed for agent "main"`
- The `openclaw agent --local --json --model ollama/mistral:7b` command fails because OpenClaw's agent mode doesn't allow model overrides from the CLI by default
- Also captured stderr/plugin warnings as "final answer" text
- **Fix needed:** Either configure OpenClaw to allow model overrides in agent mode, or use a different approach (e.g., configure the model in the workspace and don't pass `--model`)

## Failure Layer Analysis

| Layer | Failures | Root Cause |
|---|---|---|
| Model | 3 | mistral:7b doesn't always attempt tool calls on ambiguous tasks (raw-ollama-react + pi-react) |
| Runtime adapter | 15 | Hermes adapter parses wrong output; OpenClaw native blocked by model override policy |
| Runtime configuration | 5 | OpenClaw native needs model override permission |

This is exactly the kind of layer separation the benchmark was designed to expose: mistral:7b passes 5/5 through OpenClaw-react but only 2/5 through raw-ollama-react, proving the runtime adapter layer matters as much as the model.
